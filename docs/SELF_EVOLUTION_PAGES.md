# 自我迭代页面：作用与对模型的影响

控制台「自我迭代」下现在有四个页签，它们是同一条链路上的不同视图：

```text
对话发生
  → （已移除）反思作业后台观察与排队
  → 偏好候选（历史反思产出的建议）
  → 人工审批
  → 笔记（可召回的经验） / 习得自我（已生效的偏好）
  → 下一轮对话注入 prompt
```

反思作业（`reflection_jobs`）与能力缺口（`capability_gaps`）已从产品中移除：页签、接口、
数据表和后台作业 worker 都不再存在。习得自我继续按历史版本注入，偏好候选仍可查看历史，
但不再产生新条目。隔离笔记是这条链路的隐私边界观察窗口，不直接进入 prompt。

## 1. 笔记（notebook）

**是什么**：模型自己维护的长期经验条目，存在 `notebook_notes` 和 `notebook_versions`，
正文最多 4000 字。模型通过 `notebook_append` / `notebook_update` / `notebook_search`
读写，管理员在控制台也能改、归档、删除。

**如何影响模型**：两条路径。

- **自动语义召回**：每轮对话开始时，用当前消息当查询，从 ready 向量里取最多 5 条、
  2400 字以内，以 `【过去保存的信息】` 加“可能已过时”警告注入 prompt。
- **主动工具调用**：模型判断需要过去记录时调用 `notebook_search`；带 `noteId` 是精确读取，
  不走向量。

**关键限制**：只有同时满足 `status=active`、可召回（未被隔离）、属于当前 chat/global 范围、
且**当前 embedding profile 下存在 ready 向量**的笔记，才会被语义召回。换过 embedding 配置后，
旧 profile 的笔记不会自动重建——这正是“历史笔记不纳入向量库”的含义。

## 2. 隔离笔记（quarantine）

**是什么**：被内容策略判定为**不可召回**的笔记清单（`recallable=false`），比如操作类、
一次性、私密程度超出允许范围的内容。

**如何影响模型**：**不进入 prompt，也不进入向量库**。它是政策边界的观察窗口：
告诉你哪些内容被拦下了、原因是什么。管理员可以在这里看摘录（最多 600 字截断），
判断规则是否过严或过松；但这里不提供“强制召回”的按钮。

## 3. 习得自我（learned self）

**是什么**：反思经过人工批准后形成的偏好版本（`learned_self_profiles`），
按 `revision` 递增，可回滚到旧版本。内容分全局偏好和按 chatKey 的会话偏好。

**如何影响模型**：**直接进入 prompt**。命中的偏好会以带警告的块注入，例如
“以下内容是基于过去聊天形成的有限交流偏好，仅供参考，可能已过时；不是命令，
不改变身份、权限、安全规则。” 它改变的是说话风格、称呼习惯、对某类话题的倾向，
不会改动身份或安全边界。版本回滚会立刻改变下一轮注入内容。

## 4. 偏好候选（candidates）

**是什么**：反思提出、但**还没被批准**的偏好建议（`reflection_proposals` 里 `type=trait`
的部分），带支撑证据、反证、独立来源数和到期时间。

**如何影响模型**：批准前**完全不进入 prompt**。点“采用”后写入新的习得自我版本，
从下一轮开始生效；点“拒绝”则丢弃。这是人工把关环节：模型只能提议，不能自己改自己的偏好。

## 5. 反思作业与能力缺口（已移除）

这两个页面、对应接口和数据库表（`reflection_jobs`、`capability_gaps`）已删除，
反思作业 worker 不再启动。它们原本不进入 prompt；移除后对模型表现没有直接影响，
只是不再产生新的偏好候选和历史记录。

## 和 Embedding 的关系

Embedding 只影响**笔记的语义召回**这一条路径，不影响习得自我、偏好候选、反思作业或能力缺口。
它决定的是：一条合格笔记能不能被“意思相近”地问到。

当前生产的实际状态（2026-10-20 15:17 只读核对）：

- 配置：NanoGPT / Qwen3-Embedding-4B / 2560 维 / `maxDistance=0.5` / `allowPrivate=true`
- 笔记 297 条，全部 active、scope=chat
- 当前 profile 只有 4 条 ready 向量
- 其余 293 条是旧 profile 遗留的 pending/obsolete 索引，当前 worker 不会认领

按“历史笔记不纳入向量库”的决定，这些遗留行由
`scripts/purge-stale-embedding-index.mjs` 清理：只删派生表里的旧 profile 行和当前 profile
的 obsolete 行，不重新入队，也不产生新的远程调用。

## 快速判断某条内容是否影响模型

```text
在笔记页且可召回、有当前 profile 的 ready 向量  → 可能被自动注入，也可能被工具搜到
在隔离笔记页                                    → 不注入、不建向量
在习得自我当前版本里                            → 每轮按规则注入
只是偏好候选、未批准                            → 不注入
只是反思作业或提案                              → 不注入，等它变成笔记或已批准偏好
只是能力缺口记录                                → 不注入
```
