# 会话兴趣与一次性探索

这是现有 Social 模式的可选来源入口，默认关闭。不会修改其他会话，
不会因为启用开关而周期性探索或自动创建待办。

在设置的聊天页选择群聊/私聊和号码，打开「管理兴趣与探索机会」；
会话详情的 Social 面板也有入口。账号由宿主确认，号码必须在允许范围。
先保存来源、预算和开关，再选择已有活跃共同话题、交流目标与有效期，
勾选确认并安排一次机会。机会到期仅进行评估，可能使用模型、只读工具
以及发送消息，不能保证一定发言。没有宿主观察到的话题时不能凭空安排。

来源是管理员配置的材料，不是群友偏好确认。最多保留 16 个来源，名称
最多 100 字符，正文最多 1600 字符。修改或停用会递增来源版本，使旧引用
及由它生成的外部资料失效；不删除历史。并发保存使用配置版本检查，冲突
会拒绝整次保存，保留当前输入，关闭重开后核对再提交。

每日次数与 Token 预留按 UTC 日期计算。每次执行先持久预留整个单次额度，
失败/取消不退款，重启不重置；同一机会不会再次预留执行。每次最多 1–12
次模型调用、4 次只读工具调用，每次输出上限 2048 Token。模型输入按宿主
估算准入，同时参考已报告用量，因此不是供应商精确计费或金额硬上限。
探索不启用隐藏重试或服务商回退；一般会话原有重试策略不受影响。

暂停总开关保留未执行机会，恢复后仍须满足有效期、日预算、运行权限、
会话模式、未读消息和主动间隔等条件。停用具体来源会撤销其旧版本资格。
取消需要填写原因；运行中的取消/来源修改在下一次模型或工具/实际发送
检查时生效，已经开始的网络请求及已经成功投递的消息无法撤回。
租约过期或投递结果未知保持 held，不自动重放。机会过期后，新的独立
来源仍可被评估，不因历史无人回应永久锁死会话。

数据归属宿主 SQLite：`social_interest_settings`、`social_interest_history`、
`social_exploration_budget`；来源和机会都按账号/会话隔离。读取未使用状态
不创建这些表。升级仅增表，不删除现有数据。回退时先暂停机会，再恢复
原版本及一致的项目备份；保留新增表和历史，不手工删除用户数据。服务器
具体备份/回退路径必须在恢复部署授权后只读盘点确定。

本地测试：`node --test test/social-interests.test.mjs test/social-interest-app.test.mjs`。
真实浏览器交互：安装 Chromium 的隔离环境运行
`node test/browser/social-interests.mjs`。后者只在临时合成数据上运行，模型、
版本查询和协议边界均模拟，输出截图及 JSON 证据路径；不能证明真实 QQ
投递或真实模型自然度。当前服务器操作仍暂停。
