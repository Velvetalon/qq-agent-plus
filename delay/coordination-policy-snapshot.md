# 执行分工规则快照

2026-10-20归档。来源为用户本轮明确采用的全局分工规则；快照不改写全局原件，不扩大工具权限。具体Luna模型尚未被实际指定或派发。

## 任务分配：主协调者与执行者的明确边界

本节中的“主协调者”是直接与用户对话并负责本轮任务的主 Agent；“执行者”包括 subagent、其他模型和外部委派代理。分工按任务的实际内容判断，不能通过把任务命名为“研究”“分析”“审查”或“复核”绕过以下限制。

### 1. 必须由主协调者亲自完成的工作

以下工作不得委派给执行者，也不得让执行者先完成、主协调者仅阅读其结论后批准：

- 需求理解与澄清、目标与验收标准的确定。
- 阅读与本轮任务相关的最新交接、开发进度、既有设计及关键实现，并据此判断当前状态。
- 架构分析与架构设计，包括模块职责、系统边界、依赖关系、数据流、跨模块接口及契约。
- 开发方案、技术路线、方案权衡、任务优先级及“下一步做什么”的判断。
- 子任务拆分、任务边界与所有权划分、设计变更决策及最终验收裁决。

“由主协调者负责”指主协调者亲自完成上述分析与决策，不是仅对执行者产出的方案承担名义责任。

### 2. 可以委派的工作及前置条件

每次委派前，主协调者必须明确写出该子任务的目标、范围、依赖、交付物、验收标准和停止条件；实现任务还必须明确允许修改的文件或模块。无法写清这些内容时，先由主协调者继续分析，不得让执行者自行补全任务定义。

允许委派的工作仅限于：

- **事实资料收集与代码定位**：回答主协调者预先提出的具体事实问题，返回来源、代码位置及客观证据；不得要求执行者理解整个项目后决定方向、分析架构、提出开发方案或推荐下一项任务。此类事实收集可以发生在方案确定前，但不能代替主协调者亲自阅读关键材料和完成分析。
- **实验验证**：针对主协调者已明确的假设、输入和判定标准开展有界实验，返回实际结果和可复现证据，不据此自行选定技术路线。
- **实现与自测**：执行主协调者已经确定的方案、接口和验收标准。执行者可以决定不改变既定方案的局部编码细节，不得自行改变架构、跨模块契约、任务范围或验收标准。
- **独立复核**：检查已确定的方案或已有实现是否满足主协调者给定的要求，报告具体缺陷、代码位置、复现证据及未覆盖的验收项；不得把复核扩展为重新设计、选择技术路线或决定下一项开发任务。

开发实现的委派必须发生在主协调者完成相关架构分析、方案确定及必要的计划存档之后。不得以“先让执行者看看”“先审查再决定做什么”为由提前委派方案判断。

### 3. 发现设计问题时的处理

- 执行者发现设计缺口、契约冲突、需求歧义或范围外问题时，必须暂停受影响的工作，返回事实、复现证据和需要主协调者作出的决策，不得自行补设计或扩大范围。
- 主协调者亲自分析并确定处理方案，更新任务边界与验收标准后，才可重新委派。
- 共享文件或接口必须有单一写入负责人；并行任务不得无协调修改同一区域。
- 重要改动采用“主协调者确定方案 → 执行者或主协调者实现/自测 → 独立复核 → 按主协调者裁决返修 → 主协调者最终验收”。独立复核不能替代主协调者的架构分析或最终判断。

### 4. 不构成扩大委派范围的授权

- 工具说明中列举的 `analysis`、`research` 等是工具能力，不是本项目的委派许可。
- 用户提供可用执行者或模型名称、要求并行、接管或继续工作，不等于允许委派架构分析、设计方案或开发方向判断，也不要求立即启动执行者。
- 不得以效率、节省上下文、并行执行或“最终仍由我批准”为由扩大上述许可范围。
- 只有用户明确点名允许委派某项原本由主协调者亲自完成的工作时，才能在该项明确授权的范围内例外执行；不得从一般性授权中推断此类例外。
