# P7 管理端与可观测性

> 状态：planned。依赖 P3、P4、P5、P6 的稳定 API/数据契约。

## 目标

补齐插件状态、自我迭代四页签、参与/检索/反思审计和恢复文档，让停用、审批、预算、冲突和回滚可被管理员看见并安全操作。

## 必须实现

- 插件页：内置模块、版本、required、状态、能力、最后错误和允许的启停；不提供上传/安装/执行代码。
- self-evolution 页签：笔记、习得偏好、反思作业、能力缺口；支持来源、scope、版本历史、审批 diff、应用/拒绝、回滚、预算和降级。
- Session 详情/列表展示 participation、termination、外发状态、命中笔记版本、context 预算和插件快照，刷新前后一致。
- 接入现有认证路由；所有写 API 校验 body 大小、字段、revision、权限并纯文本渲染。
- 实验设置页只放 enable/disable 与 graduated；停用后仍能查看数据，不隐式建库或启动 worker。
- 更新使用、恢复、迁移和回退文档。

## 非目标与硬约束

- 不引入第二个管理端口、不在 URL 传密钥、不覆盖未保存设置。
- 不把 UI 状态当作运行事实；以服务端持久化和审计为准。

## 允许的自主决策

可沿用现有 UI 技术栈决定组件、分页和错误提示；API 路径、认证、revision/CAS、状态字段和数据可见范围不可改。

## 验收

- 未认证写请求被拒绝且不泄露凭据；HTML/script 作为文本展示。
- 停用后页面仍可读历史数据，刷新不丢状态，旧 Session 可展示新字段默认值。
- 审批/回滚与数据库版本、Session 审计和后续上下文可交叉核对。

## 回退

UI 可单独隐藏新增导航而保留后端数据；停用插件不会删除数据；路由回退仍遵循既有认证和旧 Session 兼容。
