## 1. 交付目标与不做事项

交付一个可明确选择的 social 对话模式，具有多话题现场、参与规划和自然表达分离、有来源的主动意图、相关新消息导致的草稿失效、统一记忆读写及可解释的管理入口。最终通过真实主链接线和轻量对话回放，不能只交独立 helper。

继续使用本项目已有插件、存档、消息租约、Sender/Outbox、账号隔离和管理鉴权。保留 legacy/threaded/lifecycle 回退；不无声修改已有模式、人物卡、模型供应商或禁言设置。

不做第二套消息队列、独立人格微服务、通用多 Agent 框架、可自动执行记忆文本的规则语言。不自动清空历史、解除禁言、部署、付费模型调用或发送生产 QQ 消息。生产清理与上线单独确认。

## 5. SC1：事件与多话题现场

### 范围

- Orchestrator 发出 v3 完成事件，Manager 完整保留因果字段；缺失关键来源按不可晋升处理。
- 场景按 accountId/chatKey 隔离，持久的 topicId、interactionId、消息链接与场景版本。
- 优先原生引用关系，模型可用真实 ID 提议语义重归属；同人不同话题不硬合并。
- 记录被回答目标、最近人类/机器人事件、等待/旁听/关闭状态和材料上界。
- 多会话累计按独立 interaction/original source，不按 run 数累计；生命周期与缓存不改变证据身份。
- 只读查询不创建库，容量限制不删除仍被意图/投递引用的来源。

### 主要文件与所有权

建议 src/conversation/state.js、events.js；必要的 core/store 接口只加宿主能力，避免运行组件直接写别的模块表。Orchestrator 与 plugins/manager.js 的同一事件字段由一个契约统一，不能各自猜测。

### 验收

A-E01-E06、A-S01-S08。至少覆盖原生 mid 与本地 messageId 数值冲突、同一互动拆批、并行话题、重复事件和重启。

### 可自主决定

SQL 索引、场景摘要格式、话题关联启发式和有限语义重判。不能擅自放宽账号/会话边界或把全群最近消息视为一个话题。

## 6. SC2：参与规划、上下文与自然表达

### 范围

- 新模式的入站门控首先做权限与资源检查，不以旧概率滑条随机丢掉明确对话输入。
- Planner 独立决定 reply/share/react/listen/wait/close，并选择可追溯目标、表达目的和材料来源。
- Planner 只读工具集与 Replyer 可见动作集分开；不能靠一句 Prompt 禁止 Planner 外发。
- Context Builder 为两个阶段分别构建当前上下文，不复用旧模型 transcript；交接只能作为有来源历史参考。
- Replyer 负责表达而非复述 Planner 文案；保留当前人物卡、工具能力和真正的图片/网页信息。
- 清除 social 路径上的强制短句数、问句结尾、贴纸配额、已读乱回和发送后补话倾向，包括工具描述和图片工具结果中的冲突指令。
- 原生系统指令可以明确快路径；#龙time 单独保留其宿主验证和副作用审计，不能跨消息拼接。
- 共享既有 Run deadline/token budget，按阶段记录调用次数、耗时和最终结果；失败不伪造社交回应。

### 验收

A-P01-P08、A-R01-R07、A-H02。必须经过真实 Orchestrator + PluginManager 的普通回复、沉默、看图、只读工具调用和系统插件场景。

### 不做

不把 Planner 再写一遍完整答案交给 Replyer 润色；不设置多模型投票或每句话评分器作为必经路径；不擅改人物卡满足固定测试台词。

## 7. SC3：主动意图、发送时机和有效性

### 范围

- 用持久意图替代 social 的旧 follow-up、随机冷场强唤醒和自主 pacing 重排。
- 支持共同未完话题、已授权外部新观察和兴趣探索候选；后两类不是伪装的用户命令，也不算人类偏好证据。
- 无新事件、无有效意图的 tick 不调用模型；可选探索必须有开关、来源、独立预算且不会因为“需要发言”而启动。
- pending/leased/completed/expired/cancelled/held 状态和恢复规则，source/goal 去重、期限、未回应预算、有限延期。
- 新输入在生成期间按相关性更新：只有回复前提改变才取消；不相关话题不能让输出永久饥饿。
- Delivery Guard 在队列延迟后重新检查权限、材料、目标、重复意图和 lease；随后由原 Sender 建立 outbox 意图。
- 发送失败与内容过时分别处置；partial 保留成功部分，unknown 继续人工核对，不能因社会意图再建而重放。

### 验收

A-I01-I10、A-D01-D08、A-H03/H04。覆盖“可主动分享新内容”和“无人理会不催场”两个方向，不接受通过彻底停用主动性来通过测试。

### 可自主决定

冷却/有效期起点、有限重规划的实现方式和启发式。改变调用预算或取消状态语义必须记录理由，不能把所有到期任务一律 held 伪装为恢复安全。

## 8. SC4：记忆材料、召回撤销与经历写入

### 范围

- episode、preference candidate/adopted、initiative、operational 的逻辑分离；记忆中提到计划不等于已经创建待办。
- 写入保留角色原文和来源，模型自报标签不能覆盖宿主策略；允许一次经历和暂时想法，不强迫每轮写。
- 自动检索、notebook_search、精确笔记读取、反思和派生上下文使用同一 recall policy。
- 旧运行脚本只读隔离；正常技术讨论、具体经历、互动边界和未来愿望不能因命中 retry/以后 等单词被清除。
- MaterialRef/epoch 贯穿召回、草稿和发送检查；归档后旧向量与缓存不可继续使用。
- 提供 dry-run 预览、manifest、expectedRevision/CAS 归档和回退工具；保留 Notebook/history/profile 审计，默认不执行生产清理。
- trait 不足或非法与合法 episode 分开处理；普通经历写入不等待三会话阈值。

### 验收

A-M01-M10、A-L01、A-L02、A-H05。复现旧 Notebook 脚本从不同入口召回的路径，并证明清理影响所有消费者而非只改管理页列表。

### 不做

不以全局敏感词黑名单判断语义；不把整个旧库自动总结成“干净人格”；不因新增分类重写所有笔记正文和向量。

## 9. SC5：偏好候选与反馈采用

### 范围

- 持久候选 claim/subject/scope/支撑/反证/根来源/状态和过期时间。
- 按同一候选聚合，不拿三个任意消息凑数；宿主校验独立性，模型做语义归纳，管理端能看到实际证据。
- 派生摘要、引用、AI 自己的输出、旧 profile 不增加独立支持；运行失败不成为“讨厌此人”等性格。
- 初期行为 trait 保持 review-only；用户明确纠正立即影响当前交互并可撤销旧候选，不等三次。
- 机器人自己的暂时立场允许留在经历和候选层，不因缺乏人类命令被一律消除；稳定采用不得自证。
- 跨群只做经授权的抽象晋升，不混入私聊原文；没有合格跨群证据就保持原范围。
- 限制过期和重复候选，保留可追踪采用/拒绝/撤销/回滚记录。

### 验收

A-L03-L09、A-H06。最重要正例：三次独立、同一偏好、有真实源消息的互动能形成候选；最重要反例：同一句模型回复重复三次或一条消息重试三次不能晋升。

### 可自主决定

候选去重/合并方法、相互矛盾候选的展示和有限 TTL。不能用可配置开关恢复“模型置信度0.8就自动写长期规则”的旁路。

## 10. SC6：控制台与运维可见性

### 范围

- 现有聊天设置中增加 social 模式和必要参数，显示旧模式回退，不新增承载业务表格的实验设置卡片。
- 会话详情展示参与动作、话题/目标、沟通目的、材料来源、实际外发结果与未发送原因，明确“决定回复”和“已经发送”的区别。
- 查看、取消待办；查看隔离笔记和候选证据；管理端读现有状态不启动新模型、不新建状态库。
- 所有写接口已有鉴权、宿主账号、白名单/作用域、必要确认、CAS 和有界输入；禁止 URL token 写入或跨群 ID 混用。
- 关闭模式后可读历史并取消既有待办；不能因界面查看偷偷重新启用。
- 不显示隐藏推理；普通日志只给计数/标识/原因，聊天正文留在现有受保护审计范围。

### 验收

A-C01-C07。配置保存/重载、跨账号拒绝、停用只读、候选材料展示、已有会话页和移动布局回归。

## 11. SC7：集成、轻量行为回放与交付

### 范围

- 用真实 Orchestrator、Manager、SQLite、工具、Sender 和事件流贯通，外部 LLM/OneBot/时钟边界可替换。
- 不通过手写 production 不存在的 v3 标志、窗口 ID 或预填 ready 索引来代替真实接线。
- 对所有高风险共用行为跑 focused 回归：lease/ack、unknown、time control、插件账户、#龙time、记忆版本、配置和 UI。
- 用验收文档中的代表性对话做离线回放；观察针对性、自然度、主动时机、语义复读、是否会适时沉默和成本/延迟。
- 真实模型行为测试只在允许的模型/数据范围执行；没做则写 LIVE_NOT_RUN，不用 mock 的好看台词冒充拟人效果。

### 完成门槛

所有安全/持久化硬项通过，核心对话正反例贯通；没有“全沉默”“所有候选永久不过门槛”或“只改 Prompt 未改权限”的伪完成。已知非本次环境失败单列，影响主链的失败必须解决。

交付 docs/verification/social-engine-closure.md，写明 SHA、变更、命令/退出码、失败分类、回放观察、限制、启用/回退步骤和未执行生产项。不得只报测试数量。

## 12. SC8：授权后的数据清理与灰度

本阶段当前不执行。未来需要明确允许线上部署/数据清理，且重新读取运维文档和实时状态。

顺序：一致性备份 -> dry-run 清单 -> 确认目标 revision -> CAS 归档明确污染 -> 验证召回/向量/缓存失效 -> 部署并验证控制台/服务 -> 显式选择测试范围 social -> 在用户允许下解除相关禁言/运行限制 -> 观察。

不改或重启其他服务，不改变端口、目录或账号归属。回退保留新状态表和审计，停止新 worker、切旧模式；unknown 写入不能因回退重试。记录代码版本、策略版本、模式、人设 hash、模型、禁言状态和比较时间窗口，避免把“没发出去”当效果提升。

## 13. 普通执行 Agent 的决策空间

主协调者负责架构、协议、全局取舍和最终验收；执行者按阶段边界编码、测试、修复。可以自主选择 SQL/函数/局部文件组织、工具输出 JSON 编码和非语义 UI细节。

以下情况先返回协调者：新增外部服务/模型调用、扩大生产数据范围、更改主体身份或记忆跨群权限、放宽 unknown 防线、改变等待/完成/held 语义、让局部失败影响所有记忆写入、引入自动全局人格修改。

每阶段记录已完成/进行中/阻塞/未验证，而不是结束时一次性勾完。交接必须包含工作区、文件所有者、接口版本、正在运行的命令、原始失败和下一步，不保存凭据或 lease token。
