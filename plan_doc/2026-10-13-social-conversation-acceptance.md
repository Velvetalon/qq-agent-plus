# 拟人群聊内核：单元与闭环验收标准

- 日期：2026-10-13，Asia/Shanghai。
- 适用设计：[完整架构](2026-10-13-social-conversation-engine.md)。
- 阶段对应：[开发规划 SC0-SC8](2026-10-13-social-conversation-development-plan.md)。
- 状态：验收规范，不是测试通过报告；当前代码开发暂停。

## 1. 验收层次与证据口径

| 层次 | 要回答的问题 | 可替换边界 | 不可替换的内容 |
| --- | --- | --- | --- |
| 单元 U | 某个契约、状态变化和权限是否正确 | 时钟、模型返回、网络端点 | 被测状态逻辑、校验、幂等和作用域 |
| 主链 I | 模块是否通过生产入口真正连通 | LLM/embedding/OneBot 的最外层 HTTP，允许可控等待 | Orchestrator、Manager、SQLite、工具、上下文构建、Sender、事件队列 |
| 行为 B | 回复是否像参与对话而非复述消息 | 允许离线脱敏或合成群聊回放 | 使用真实选定模型时必须如实记录模型、人设、参数；mock不证明自然度 |
| 操作 O | 迁移、清理、切换、恢复是否可靠 | 临时旧库副本、测试账号 | 版本检查、操作确认、归档、回滚、unknown保护 |

不要求为每一行单独建一个测试文件，相关场景可以共享 fixture。优先跑契约边界和生产事故回归，不用全仓库测试数量替代实际效果。

所有用例的 DATA_DIR 必须指向临时目录；mock只能出现在边界，不能绕过真实 v3 发射器、预先手填 shared windowId、伪造投递结果或直接塞最终 profile 来代替学习流程。只有迁移/清理旧库用例可以显式构造污染历史 fixture。

结果分类：PASS、FAIL、NOT_RUN、LIVE_NOT_RUN。步骤未执行不能写PASS；expected拒绝与异常崩溃要区分；局部状态通过不代表全套引擎可用。

## 2. 通用 fixture 契约

每条消息带 accountId/chatKey、存档 messageId、独立 platformMessageId、senderId、role、ts、原生reply/mention 信息；用两个账号、两个群和一个私聊验证隔离。默认所有标识均为合成，不含真实QQ/Token。

每个时间相关用例用可控时钟，不靠长时间 sleep。新输入在规划、生成、发送排队、实际 HTTP 四个时点可分别注入。发生未知投递时，模拟“对端可能收下但本端超时”，而不是普通连接拒绝。

确认字段严格区分 received/observed、delivered 与 explicitFeedback。默认没有用户确认，模型说“用户喜欢”不能替代事实。

每条阶段验收记录：用例 ID、输入简述、生产入口、期望副作用、实际计数/状态、失败码、命令、退出码、fixture路径、限制。正文语义看行为回放，不靠固定答案全文相等。

## 13. 轻量拟人效果回放：A-B

这是架构效果评价，不是强制固定句子匹配。每场景允许多个合理行为；评价员记录“为何自然/为何突兀”，不强迫模型说我们预写的台词。

| ID | 场景 | 优先观察 |
| --- | --- | --- |
| A-B01 | 直接问一个具体短问题 | 是否正面接内容，能一句结束，不补无关人设 |
| A-B02 | 群友彼此完整对话 | 能否旁听，不误把邀请归自己 |
| A-B03 | 两组人同时聊技术和娱乐 | 能否选对对象/话题，不混线 |
| A-B04 | 对方生成途中说“找到了不用了” | 不迟到复述旧答案，可自然停下 |
| A-B05 | 机器人开玩笑后无人回应 | 不催场，不用“算了/人呢”制造第二轮 |
| A-B06 | 新公共资料与共同兴趣相关 | 有机会主动分享，内容具体；不能只会等命令 |
| A-B07 | 同类梗图连续出现 | 可以换角度/只反应/沉默，不只是换词复读同一个包袱 |
| A-B08 | 群友认真低落或认真求助 | 能放下固定毒舌/短句模板，不敷衍或强行玩梗 |
| A-B09 | 技术话题包含retry、queue、错误码 | 不因记忆治理失去正常技术交流能力 |
| A-B10 | 被问身份与现实经历 | 自然有角色感，但不假装做过现实行动 |
| A-B11 | 一次有意义的共同经历，之后再提起 | 相关时记得；无关时不硬cue旧话题 |
| A-B12 | 连续多轮比较强的人设要求 | 稳定但不每轮证明自己；普通平淡回复也允许 |

每个场景记录目标、当前模型/温度、人设hash、引擎/策略版本、输入范围、实际决策和可见输出。用同一批输入对比旧/新；输入批次时机也要记录，否则无法区分调度和措辞差异。

建议评分维度：对象/话题正确性、内容新增性、时机自然度、人设一致性、适度主动性、能否结束，各0-2分。分数只辅助排序，不拿一个总分盖过明显催场或隐私问题。先用12类小样本找架构失败，不建设大规模评测平台才开始迭代。

初始效果门槛：不能出现跨对象明显抢话、无因递归催话、已解决问题反复补答；至少展示一个主动分享正例、一个旁听正例、一个正常记忆正例和一个认真回答正例。若模型选择不理所有场景，必须判失败而不是“复读率0”。

## 14. 指标与非目标

建议看：每种触发的参与率、无新内容外发、连续未回应主动回合、同话题语义复述、过时草稿拦截、有效记忆命中、候选成功累计/撤销、模型调用数、延迟和unknown状态。

不作为单独目标：最低消息量、固定字符数、固定表情频率、工具调用次数、空profile、全部门禁拒绝、零主动率。精确文本去重是基础检查，不能代表自然度或语义不重复。

延迟/成本先报告实测，不写无依据承诺。总Run预算遵守现有上限，两个阶段计入同一预算；无输入tick必须零外部调用，这是可硬验收的不变量。

## 15. 上线和回退操作验收

- 旧库副本迁移可重复运行，版本/正文/审计保留。
- 清理仅处理预览manifest且CAS匹配的条目；没授权或条目已变更时拒绝应用。
- 清理后精确读取、向量、缓存、反思和在途材料一致失效；不能只验证profile为空。
- 切回旧模式后新计时器/worker停下，存档和未知投递不重放。
- 部署/生产清理/解除禁言/真实模型测试分别记录是否获准，不相互推断。
- 生产比较必须标明模型、人设、禁言/发送可用性、样本窗口和成功发送数；无成功发送的前后样本不能用于声称质量百分比提升。
